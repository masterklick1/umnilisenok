# План: исправить Google Maps в Android-сборке Codemagic

## Подтверждённая причина
- Проект использует `@capacitor/google-maps` в нативном Android-приложении.
- `LocationMap.tsx` передаёт пустой `apiKey` и рассчитывает на ключ из Android-манифеста.
- Папка `android/` не хранится в проекте и создаётся во время сборки Codemagic.
- В текущем `codemagic.yaml` нет шага, добавляющего `com.google.android.geo.API_KEY` в сгенерированный `AndroidManifest.xml`.
- Поэтому нативный Google Maps SDK собирается без Android-ключа и карта остаётся пустой.

## Что будет изменено
1. **Настроить секрет нативной карты в Codemagic**
   - Использовать защищённую переменную `GOOGLE_MAPS_ANDROID_KEY`.
   - Не вшивать секретный Android-ключ в репозиторий или клиентский `.env`.
   - Для ключа в Google Cloud должна быть включена **Maps SDK for Android**, а ограничение Android-приложения должно содержать пакет `app.lovable.umnilisenok` и SHA-1 сертификата подписи Codemagic.

2. **Исправить оба workflow в `codemagic.yaml`**
   - После `npx cap sync android` проверять наличие `GOOGLE_MAPS_ANDROID_KEY` и останавливать сборку с понятной ошибкой, если переменная не задана.
   - Автоматически добавлять в `<application>` сгенерированного `AndroidManifest.xml`:
     ```xml
     <meta-data
       android:name="com.google.android.geo.API_KEY"
       android:value="${GOOGLE_MAPS_ANDROID_KEY}" />
     ```
   - Сделать вставку идемпотентной, чтобы тег не дублировался.
   - Оставить генерацию иконок, разрешения и сборку Gradle в правильном порядке.

3. **Укрепить передачу ключа в нативную карту**
   - Синхронизировать `LocationMap.tsx` с настройкой Android SDK: нативный режим будет явно использовать ключ сборки, а браузерный режим продолжит применять только браузерный fallback.
   - Добавить понятное логирование ошибки и состояние ошибки вместо необъяснимого белого блока, если SDK не смог создать карту.
   - Не менять геозоны, маркеры, маршруты и логику отслеживания.

4. **Обновить пример переменных окружения**
   - Документировать имя переменной для нативного Android-ключа без публикации самого ключа.
   - Браузерный ключ останется только для web/preview.

5. **Проверка**
   - Проверить production web build.
   - Проверить, что итоговый Codemagic-скрипт создаёт манифест с meta-data внутри `<application>`.
   - Проверить отсутствие ключа в исходниках и логах сборки.

## Что потребуется от пользователя после изменений
1. В Codemagic добавить секретную переменную `GOOGLE_MAPS_ANDROID_KEY`.
2. В Google Cloud включить **Maps SDK for Android** и указать пакет `app.lovable.umnilisenok` + SHA-1 upload-keystore.
3. Сделать `git pull` и запустить новую сборку APK/AAB.

Без отдельного Android-ключа и правильного SHA-1 нативная карта Google не заработает, даже если код приложения собран без ошибок.
